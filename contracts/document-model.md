# Contract: Document Model

**Version** 0.1 (pre-1.0)

**Status** Draft for owner review

**Consumer** `webinertia/asciidoc-php-multi-repo`, `src/Render/TocExtractor.php`, and any
consumer that builds navigation or cross-page anchors

## Scope

This contract governs what a consumer may read off a parsed document: the node kinds, the
accessors on each kind, the table of contents structure, and the section id generation algorithm.

It does not govern how the parser is implemented, the internal block tree representation, how
block content is stored (it is lazy), inline node types, or the rendering of any node. It does
not govern attributes beyond the three that steer id generation (`idprefix`, `idseparator`,
`sectids`); the full attribute set is in `contracts/attributes.md`.

Section ids are in scope because a consumer builds links from them. The consumer that motivated
this contract aborts the whole site build when a section that belongs in the table of contents
has no id, so id generation is not cosmetic.

## Surface

### Node kinds

```php
namespace Phpiidoc\Document;

interface NodeInterface
{
    public function getId(): ?string;

    public function getTitle(): ?string;

    public function getContext(): string;

    public function getSourcePath(): ?string;

    public function getSourceLine(): ?int;
}

interface DocumentInterface extends NodeInterface
{
    /** @return list<NodeInterface> */
    public function getBlocks(): array;

    public function getDocTitle(): ?string;

    public function getHeader(): ?HeaderInterface;

    public function getAttributes(): Attributes;

    public function getDiagnostics(): Diagnostics;
}

interface SectionInterface extends NodeInterface
{
    /** Zero-based. The rendered heading level is getLevel() + 1. */
    public function getLevel(): int;

    public function getId(): string;

    /** @return list<NodeInterface> */
    public function getBlocks(): array;

    public function isSpecial(): bool;
}

interface BlockInterface extends NodeInterface
{
    /** @return list<NodeInterface> */
    public function getBlocks(): array;
}
```

`getContext()` returns the AsciiDoc context token as a lowercase string: `document`, `section`,
`paragraph`, `listing`, `literal`, `pass`, `admonition`, `example`, `sidebar`, `open`, `quote`,
`verse`, `ulist`, `olist`, `dlist`, `table`, `image`, `toc`, `floating_title`, `page_break`,
`thematic_break`.

### Accessors

| Accessor | On | Returns | Notes |
|---|---|---|---|
| `getLevel()` | `SectionInterface` | `int` | Zero-based. A document title is not a section and has no level. |
| `getId()` | `SectionInterface` | `string` | Never `null` and never empty for a section returned from a successful parse. |
| `getId()` | `NodeInterface` | `?string` | `null` for a node with no id. |
| `getTitle()` | `NodeInterface` | `?string` | The section title as source text with inline substitutions applied, or `null`. |
| `getBlocks()` | `DocumentInterface`, `SectionInterface`, `BlockInterface` | `list<NodeInterface>` | Direct children only. Empty list, never `null`. |
| `getDocTitle()` | `DocumentInterface` | `?string` | `null` when the document has no title. |
| `getContext()` | `NodeInterface` | `string` | Token from the list above. |
| `getSourcePath()` | `NodeInterface` | `?string` | File the node came from. `null` when unknown. |
| `getSourceLine()` | `NodeInterface` | `?int` | One-based. `null` when `sourcemap` is off or the position is unknown. |

`getLevel()` is zero-based because that is what Ruby stores (`section.rb:46-51`). A consumer that
compares against heading levels adds one. This contract does not change that convention, and a
consumer must not assume one-based levels.

### Table of contents

```php
namespace Phpiidoc\Document;

final readonly class Toc implements \Countable, \IteratorAggregate
{
    /** @return list<TocEntry> */
    public function entries(): array;

    public function hasEntries(): bool;
}

final readonly class TocEntry
{
    public function __construct(
        public string $id,
        public int $level,
        public string $title,
        public string $sourcePath,
        /** @var list<TocEntry> */
        public array $children = [],
    ) {}
}
```

`TocEntry::$level` equals the section's `getLevel()`, so it is zero-based. `TocEntry::$id` equals
the section's `getId()` and the `id` attribute of the rendered heading. A `TocEntry` is built for
every section, regardless of any `toc` or `toclevels` attribute.

### Id generation

Ids are generated by default. The `sectids` attribute gates generation and is set to the empty
string by default (`lib/asciidoctor.rb:378`).

The algorithm, in order:

1. `pre` is the value of the `idprefix` attribute, or `_` when the attribute is unset.
2. `sep` is the first character of the `idseparator` attribute, or `_` when the attribute is
   unset. A multi-character separator is truncated to its first character. An empty separator
   means spaces are deleted rather than replaced.
3. The title is lowercased.
4. Every match of the invalid-character filter is removed. The filter is
   `/<[^>]+>|&(?:[a-z][a-z]+\d{0,2}|#\d\d\d{0,4}|#x[\da-f][\da-f][\da-f]{0,3});|[^ \p{Word}\-.]+?/`
   (`lib/asciidoctor/rx.rb:263`). It removes inline markup, HTML entities and any character that
   is not a space, a word character, a hyphen or a dot.
5. `pre` is prepended.
6. If the separator is empty, spaces are deleted.
7. Otherwise, runs of the characters space, `.` and `-` are collapsed to a single separator, and
   a trailing separator is removed.
8. If `pre` is empty and the result starts with the separator, the leading separator is removed.
9. If the result is already in use in the document, a counter is appended after the separator.
   The counter starts at 2 and increments until the id is unique: `_foo`, `_foo_2`, `_foo_3`.

Worked examples with the defaults:

| Title | Id |
|---|---|
| `Foo` | `_foo` |
| `Foo Bar` | `_foo_bar` |
| `Foo  Bar` | `_foo_bar` |
| `Foo Bar ` | `_foo_bar` |
| `Foo: Bar` | `_foo_bar` |
| `Foo <em>Bar</em>` | `_foo_bar` |
| `Foo.Bar` | `_foo_bar` |
| `Foo - Bar` | `_foo_bar` |
| second section titled `Foo` | `_foo_2` |
| third section titled `Foo` | `_foo_3` |

With `idprefix` set to the empty string, `Foo Bar` becomes `foo_bar`. With `idseparator` set to
`-`, `Foo Bar` becomes `_foo-bar`.

### Explicit ids

An explicit id wins over a generated one. Three forms are recognized:

1. A block anchor line immediately before the section title: `[[my-id]]`.
2. An id in the block attribute list immediately before the title: `[#my-id]`.
3. A trailing anchor on the title line: `== Title [[my-id]]`.

An explicit empty id (`[#]` or `[[]]`) is treated as no id, and generation applies. An explicit
id is used verbatim; it is not lowercased, prefixed, separated or filtered.

If an explicit id duplicates one already in use, the parser keeps the id and emits the
`duplicate_section_id` warning from `contracts/diagnostics.md`. It does not renumber.

### `sectids` gate

When the `sectids` attribute is unset, no ids are generated. A section then has
`getId()` returning `null` at the node level, which contradicts the non-null guarantee on
`SectionInterface`, so phpiidoc refuses the configuration instead: unsetting `sectids` emits
`unsupported_construct` with target `sectids!` and the section is given a generated id anyway.
Consumers build navigation from ids, and a document with unset `sectids` cannot be published.

`idprefix` and `idseparator` are honoured as described above. They are document attributes, so
whether a document header can set them depends on the attribute precedence decision in
`contracts/attributes.md`.

## Guarantees to consumers

1. `getLevel()` is zero-based. The rendered heading level is `getLevel() + 1`.
2. Every section reachable from `DocumentInterface::getBlocks()` has a non-empty id after a
   successful parse, because generation is on by default and unsetting `sectids` is an error.
3. `TocEntry::$id`, `SectionInterface::getId()` and the rendered heading `id` are the same
   string. A link built from the TOC resolves.
4. Ids are deterministic. The same source and the same `idprefix` and `idseparator` produce the
   same ids on every run.
5. Collisions are resolved by appending `_2`, `_3` and so on, never by dropping a section.
6. `getBlocks()` returns direct children in source order. Depth-first traversal in source order
   is a valid walk, and that is the walk a TOC builder needs.
7. `getBlocks()` never returns `null`.
8. An explicit id is used verbatim, so a consumer may rely on a hand-written anchor surviving.
9. Changing the zero-based level convention, the id algorithm, or a `TocEntry` field is a
   breaking change.

## Non-guarantees

- The internal representation of blocks, including how content is stored.
- Inline node structure. `getTitle()` returns a string, not a node tree.
- Any accessor not listed here. `getLevel()`, `getId()`, `getTitle()` and `getBlocks()` are the
  contract; convenience accessors may be added or changed.
- The order of attributes in the resolved attribute set as seen through the document.
- Ids for nodes other than sections. Blocks may or may not have ids.
- The behaviour of a document parsed with `sectids` unset beyond the error described above.
- Section numbering (`sectnums`) and captions.
- Thread safety. A document is mutable during parsing.

## Stability

This contract is pre-1.0. Adding node kinds, accessors or `TocEntry` fields is a minor change.
Removing an accessor, changing `getLevel()` to one-based, changing the id algorithm in a way that
changes generated ids, or changing the collision suffix format is a breaking change.

Changing the id algorithm for a document that never sets `idprefix` or `idseparator` is a
breaking change even though it only affects generated strings, because consumers persist those
strings in links and in cross-page anchors.
