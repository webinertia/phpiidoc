# phpiidoc CLI requirements

Status: discovery record. Input to a later CLI spec, not a spec itself.
Purpose: capture what the CLI has to do, with a line cite for every oracle claim, while the
audit evidence is still at hand.
Scope: requirements and open decisions only. Nothing here is implemented, and nothing here
authorises an implementation.

Authority note: `tyrsson/asciidoctor` (Ruby) is the oracle. `webinertia/asciidoc-php` is
retired evidence: it is read, never trusted, and never changed.

---

## 1. Purpose and status

phpiidoc's CLI today is a single Symfony console command, `phpiidoc:build`, in
`src/Console/PhpiidocCommand.php`. Its `execute()` returns `Command::SUCCESS`, declares no
options, prints nothing, and dispatches nothing. The binary itself works end to end:
dispatch, container wiring, help output and the interactive menu are all verified. What does
not exist is a designed command surface.

This document records the requirements that surface has to satisfy. It exists because the
retired `asciidoc-php` CLI was ported from a planning document rather than from the oracle,
so its flag set is not evidence of what the oracle does. Every oracle behaviour below was
re-read from source and carries a line number.

## 3. What was never verified

No oracle comparison ever existed in `asciidoc-php`. The CLI was ported from
`planning/07-cli-interface.md`, not from `options.rb`, and the evidence is unambiguous:

- `test/unit/Cli/OptionsTest.php` asserts hardcoded PHP-side values only. Examples:
  `assertSame('html5', $d['backend'])` (line 25), `assertSame(SafeMode::SAFE, $d['safeMode'])`
  (line 27), `assertFalse($opts->attributes['toc'])` (line 48). No assertion is derived from
  oracle output.
- `test/unit/Cli/ApplicationTest.php` and `test/unit/Cli/InvokerTest.php` likewise assert
  PHP-side values: exit codes 0 and 1, and presence or absence of substrings in the port's
  own output.
- `test/unit/UsageRenderFixtureTest.php` compares the render of `test/asset/usage/usage.adoc`
  against `test/asset/usage/expected.html`. That expected file was generated by the port
  itself, so the test proves the port is self-consistent, not that it matches the oracle.
- `test/reference/usage.html` (69,980 bytes) is a single hand-made file that nothing
  references. No test, script or config points at it.
- `test/results/` holds three committed snapshots (`full-document.html`,
  `full-document-embedded.html`, `full-document-preview.html`) plus a `.gitkeep`. Nothing
  references them either.

Consequences to carry into the spec: the PHP flag set is a design artifact, not a port. Every
row in section 4 marked "absent" or "divergent" is a gap against the oracle, and no existing
PHP test is evidence of oracle behaviour.

Two things could not be resolved from `options.rb` and are therefore not asserted here:

- Whether Ruby's `OptionParser` accepts attached short values such as `-aNAME=VALUE`. That is
  `OptionParser` behaviour, not `options.rb` text, so no line can be cited.
- Whether the `%w(...)` array form accepts unambiguous abbreviations (for example
  `-d art`). Same reason.

Both are recorded as decisions in section 7.

## 5. Behavioural divergences

Each entry is a place where the retired PHP CLI and the oracle disagree today. These are the
defects the spec has to close, or consciously accept.

1. **Safe-mode default.** Oracle UNSAFE (line 14). PHP SAFE (`Options.php:27,51`), asserted by
   `OptionsTest.php:27`. The PHP default is stricter, which changes which documents build.
2. **`name!` shape.** Oracle stores key `name!` with an empty value and lets the document
   layer resolve the unset (93-100). PHP detects a trailing `!`, runs `rtrim($attrStr, '!')`
   so `name!!` collapses to `name`, and stores `false` (`Options.php:204-210`). Different key,
   different value type, and the double-bang case loses information.
3. **Attribute trimming.** Oracle never trims name or value (99-100). PHP trims both
   (`Options.php:222`), so `-a " toc = left "` stores `toc => left` where the oracle stores
   `" toc " => " left "`.
4. **Soft-set is missing.** Oracle keeps `@` in the key for `name@=value` and in the value for
   `name=value@`, which is how the help text describes precedence (89-91). PHP has no `@`
   handling at all (`Options.php:201-224`).
5. **Empty and bare-`=` attributes.** Oracle silently skips an empty string or `=` (93). PHP
   stores a key of `''` for both.
6. **`-e` is absent.** Oracle `-e` and `-s` are the same statement (59-61, 79-81). PHP has
   only `-s` (`Options.php:102`).
7. **`-n` is absent.** No `sectnums` attribute is ever set from the CLI.
8. **Doctype is unvalidated.** Oracle rejects anything outside the four values (55). PHP
   accepts `-d nonsense` and passes it to the converter (`Options.php:127-129`,
   `Invoker.php:78`).
9. **`-R` is absent and `-D` flattens.** Oracle computes the destination path relative to the
   source root (118-123). PHP writes every output directly into the destination directory
   (`Invoker.php:213-216`), so a tree of documents collapses into one directory.
10. **No template mechanism.** `-T` and `-E` are absent (102-114). Neither becomes a command
    line requirement: custom templates reach the converter as a laminas-view template map
    override supplied through configuration (R20), and engine selection is out of scope (R21)
    because PHP has no engine-selection seam.
11. **No log-level or failure-level control.** Both absent, so exit codes cannot be tuned and
    the WARN-versus-FATAL distinction does not exist (132-139).
12. **Glob handling.** Oracle only globs when the literal path is not a file, and on no match
    treats the string as a missing file (225-238). PHP never globs (no `glob(` call in `src/`),
    so `*.adoc` from a shell-less caller is treated as one literal filename and fails at
    conversion.
13. **STDIN placement.** Oracle accepts `-` only as the sole argument (218-220) and warns
    about extra arguments otherwise (222-224). PHP accepts `-` anywhere in the file list
    (`Options.php:166-171`, `Invoker.php:85-90`).
14. **Verbosity shape.** Oracle `-q` and `-v` set levels 0 and 2 on a single `verbose` key
    (140-148). PHP uses two independent booleans (`Options.php:30-31`), and `-v` is inert at
    the CLI because no logger is passed (`Application.php:122`, `Invoker.php:190`).
15. **`-t` is inert.** Parsed and stored, never read.
16. **Version surface.** `-V` short form absent; the oracle also prints runtime environment
    (202-204, 313-320), which has no PHP analogue.
17. **`-h TOPIC` absent.** Oracle supports `syntax` and `manpage` topics (155-201).
18. **`--concurrency` is PHP-only.** No oracle equivalent; it exists to drive `Async\TaskGroup`
    (`Options.php:148-154`, `Invoker.php:118-150`).
19. **Option errors.** Oracle writes the message to STDERR and the usage text to STDOUT, then
    returns 1 (301-308). PHP writes only the message to STDERR and returns 1
    (`Application.php:100-103`).

## 6. Derived requirements

Numbered and testable. Each will become one or more spec requirements; none is implemented
here. "Test" means the assertion the spec must be able to make, not a test written now.

**Safe mode**

- **R1.** The default safe mode is an explicit, documented, tested value. phpiidoc must not
  inherit `SafeMode::SAFE` from `asciidoc-php` by accident, and the spec must record that the
  oracle defaults to UNSAFE (options.rb:14). Test: building CLI options with no safe-mode flag
  yields the value named by decision D1, and a unit test asserts that value.
- **R2.** `--safe-mode` accepts the four SafeMode names, rejects anything else before any
  conversion starts, exits non-zero, and the error message names both the rejected value and
  the accepted set. Test: one case per name plus one unknown value.

**Attributes**

- **R3.** `-a name` stores key `name` with an empty-string value.
- **R4.** `-a name=value` stores key `name` with value `value`, with no trimming of either
  side, so a leading or trailing space survives.
- **R5.** `-a name!` stores key `name!` with an empty value. Resolution of the unset happens in
  the document layer, not in option parsing.
- **R6.** `-a name@=value` stores key `name@` with value `value`.
- **R7.** `-a name=value@` stores key `name` with value `value@`.
- **R8.** An empty attribute argument and a bare `=` are skipped silently.
- **R9.** Repeated `-a` accumulates; the last value for a given key wins. Each of R3 to R8 has
  exactly one test, and R3 to R7 are tested without any trimming side effects.

**Structural flags**

- **R10.** `-e`/`--embedded` and `-s`/`--no-header-footer` are aliases: both set standalone to
  false, and nothing downstream can distinguish which was used.
- **R11.** `-n`/`--section-numbers` sets the `sectnums` attribute to an empty string, which is
  the oracle's shape (options.rb:82-84), not to a boolean or `1`.
- **R12.** `--doctype` is validated against `article`, `book`, `manpage`, `inline`, and an
  invalid value fails before any input is read. Whether abbreviations are accepted is D5.
- **R13.** phpiidoc accepts `html5` for `--backend` and rejects any other value with a clear
  error naming the supported set. Whether the flag exists at all in v1 is an owner decision
  (D8), not a settled requirement. Grounds: html5 is the only hard requirement for v1 and the
  only accepted parity loss is which converter strategies ship in v1 (architecture grilling,
  section 4), so the flag's only legal v1 value is its own default.

**Logging and exit codes**

- **R14.** `--log-level` accepts debug, info, warning, error and fatal in any case, folds
  `warning` to WARN, and sets the minimum logged severity. `-q` silences output below error
  and `-v` raises output to debug and info; both compose with `--log-level` under one rule
  rather than two independent booleans.
- **R15.** `--failure-level` accepts info, warning, error and fatal, folds `warning` to WARN,
  and sets the minimum severity that produces a non-zero exit code. Default is FATAL.
- **R16.** `--failure-level` is honoured from the parsed value. The oracle's constructor
  hardcodes FATAL and discards the argument (options.rb:29), which is an oracle defect and is
  not to be copied.
- **R17.** Exit-code contract, all tested: 0 for success, `--help` and `--version`; 1 for no
  input, a missing input file, an unreadable input file, an input path that is not a file, an
  unknown option, and an option missing its argument (options.rb:210-214, 243-259, 301-308).
- **R18.** In a batch, one failing document does not abort the rest, every failure is reported
  on stderr with the file named, and the process exits non-zero when any document failed or
  when a logged message reaches `--failure-level`.

**Paths and output**

- **R19.** `-B`/`--base-dir` sets the base directory used to resolve `include::` targets.
  `-R`/`--source-dir` and `-D`/`--destination-dir` together preserve the path of a document
  relative to the source root when writing into the destination directory, so a tree of
  documents produces a tree of output files.
- **R20.** Custom converter templates are supplied as a laminas-view template map override
  through configuration, not as a directory of ERB templates passed on a command line. The
  capability survives and the mechanism differs: the converter strategy owns laminas-view
  (architecture grilling, section 3), and the template path is a proven design with a reference
  implementation to copy (architecture grilling, section 10, finding 5). Whether any CLI
  surface exists for this mechanism is an owner decision (D7), not a settled requirement.
- **R21. Out of scope: template engine selection.** The oracle's `-E`/`--template-engine`
  selects a Ruby templating engine and loads its gem on demand (options.rb:112-114). PHP has no
  equivalent engine-selection seam: the engine is fixed by the converter strategy that owns
  laminas-view. Recorded here as an out-of-scope finding, not as a requirement.

**Input model**

- **R22.** `-` as an input reads from STDIN and `-o -` writes to STDOUT.
- **R23.** Input patterns are either expanded by phpiidoc or rejected with an explicit error
  naming the pattern. Treating `*.adoc` as a literal missing filename, which is what silence
  produces today, is not acceptable. Whether expansion happens is D4.

**Decisions carried as requirements**

- **R24.** `-V` is accepted as the short form of `--version`.
- **R25.** `-h`/`--help` with no argument prints usage to stdout and exits 0. Topic support is
  D6.
- **R26.** Whether `--concurrency` survives the redesign is decided before the spec is
  written (D2). If it survives, the spec must define its default and its effect on ordering of
  diagnostics.

**Diagnostics**

- **R27.** `--trace` includes backtraces in error reports and is off by default.
  `-t`/`--timings` prints a timings report and is off by default; if adopted it must do
  something, since the retired CLI parsed it and never read it.

## 7. Open decisions for the owner

These are decisions, not agent choices. The spec cannot be written until each is answered.

**D1. Safe-mode default.** The oracle defaults to UNSAFE (options.rb:14); `asciidoc-php`
defaults to SAFE (`Options.php:27`). Options: keep UNSAFE for oracle parity; keep SAFE for
safety with the divergence recorded; or make it required with no default. Whatever is chosen
becomes R1 and must be tested.

**D2. `--concurrency`.** It has no oracle equivalent. Options: drop it and build a tree
sequentially; keep it as a phpiidoc extension with a documented default; or defer it until the
build pipeline needs it. R26 depends on this answer.

**D3. Capability parity, and the shape of the flag names.** The oracle is a Ruby binary whose
flags are `-b`, `-d`, `-a`, `-s` and so on. phpiidoc is a Symfony console command, where an
option is a `--long-name` and short flags are a separate declaration. The owner decides
whether phpiidoc targets capability parity (every oracle capability reachable somehow, names
free to differ), surface parity (the same short flags work), or a deliberate subset. This
decision governs every row in section 4 marked adopt.

**D4. Input model.** Does the command take per-file arguments, scan a directory, or both? The
oracle takes files and globs only as a fallback when a literal path does not exist
(options.rb:225-238). A directory scan is a phpiidoc addition with no oracle line behind it.
R23 depends on this answer.

**D5. Doctype abbreviations.** The oracle validates against four values (options.rb:55). Whether
an unambiguous prefix such as `-d art` is accepted is `OptionParser` behaviour and cannot be
cited from `options.rb`, so it is not asserted anywhere above. Decide: exact match only, or
prefix matching.

**D6. `-h` topics.** The oracle's `-h` takes an optional TOPIC and supports `syntax` and
`manpage` (options.rb:155-201). Decide whether phpiidoc implements topics, ignores them, or
rejects them, and whether `manpage` output (troff) is in scope at all.

**D7. Theming surface.** The oracle's `-T` requires the Tilt gem and points at a directory of
custom converter templates that override the built-in converter (options.rb:102-111); its `-E`
selects a Ruby templating engine and loads that engine's gem on demand (112-114). Neither
mechanism exists in PHP. The converter strategy owns laminas-view (architecture grilling,
section 3), so custom templates are a laminas-view template map override supplied through
configuration (R20), and engine selection is out of scope because the engine is fixed by that
strategy (R21). The template path itself is a proven design with a reference implementation to
copy (architecture grilling, section 10, finding 5), so the capability survives while the
mechanism differs. Decide whether any CLI surface exposes the template map override at all,
and if so whether it reuses the oracle's flag names or a phpiidoc-specific mechanism.

**D8. Backend flag.** html5 is the only hard requirement for v1, and the only accepted parity
loss is which converter strategies ship in v1 (architecture grilling, section 4). That makes
the only legal v1 `--backend` value the flag's own default, so the flag carries no choice in
v1. R13 requires phpiidoc to accept `html5` and reject any other value with a clear error
naming the supported set. Decide whether the flag exists at all in v1.
